# 古堡九夜 · 前端设计案

> 配套 `01-玩法系统设计.md`。本文定义页面、布局、组件、视觉与数据流，不写实现。
> 目标载体：SillyTavern 消息楼层内渲染的游戏面板（Vue 3 + 原生 CSS），沿用 `cards/YuriOpening` 已验证的工程形态。

---

## 1. 页面与状态机

```
┌──────────┐   选角/难度    ┌──────────┐
│ 开局页    │ ───────────→ │ 白天主视图 │
└──────────┘               └────┬─────┘
                                │ 20:00
                           ┌────▼─────┐
                           │ 夜晚主视图 │
                           └────┬─────┘
                                │ 08:00
                           ┌────▼─────┐
                           │ 天亮日报  │
                           └────┬─────┘
                                │
                      ┌─────────┴─────────┐
                      │                   │
                 ┌────▼────┐        ┌────▼────┐
                 │ 白天主视图│        │ 死亡结算 │
                 └─────────┘        └─────────┘
```

- 状态机只有一个入口：`阶段` 字段（`选角` / `白天` / `黑夜` / `入室` / `日报` / `死亡` / `胜利`）。
- `入室` 是黑夜的子阶段：门破后替换夜晚主视图。`外出` 不是独立阶段，是黑夜内的一次行动。
- 面板不自己记阶段，全部从 MVU 读；刷新页面、切楼层、重进聊天后状态一致。
- 白天与黑夜共用顶栏和底栏，主视图切换；不弹全屏模态，避免手机端高度问题。

## 2. 全局骨架

```
┌─────────────────────────────────────┐
│ TopBar                              │
│ 第3天 · 14:00     白天               │
│ 铜扣 20   夜露 0                     │
│ HP   ████████░░ 8/10                │
│ 体力 ███████░░░ 7/10                │
│ 恐惧 ██░░░░░░░░ 2/10                │
├─────────────────────────────────────┤
│                                     │
│ MainView                            │
│ （DayView / NightView / 日报 / 死亡）│
│                                     │
│                                     │
├─────────────────────────────────────┤
│ TabBar                              │
│ 地图 · 房间 · 设施 · 背包 · 人物      │
└─────────────────────────────────────┘
```

- 宽度：100%，最大 720px，居中。手机竖屏优先。
- 高度：不固定，随内容增长；`min-height: 420px`。
- 顶栏常驻，底栏常驻；中间区域滚动。
- 所有交互在面板内完成，聊天输入框只用于对话与叙事。

## 3. 各屏设计

### 3.1 开局页

纵向三段：创建角色、选职业、难度。

```
┌─────────────────────────────┐
│  古 堡 九 夜                 │
│  一个人，一座会重排的古堡      │
├─────────────────────────────┤
│  一、创建你的角色            │
│  姓名 [____________]         │
│  外观 8 张立绘选一            │
│  四维滑杆 1–20，总和 24        │
│  校验：总和 24 / 单项 1–20     │
├─────────────────────────────┤
│  二、选择职业 九选一          │
│  ┌─────┐ ┌─────┐ ┌─────┐   │
│  │推演者│ │修补匠│ │守夜人│   │
│  └─────┘ └─────┘ └─────┘   │
│  ... 9 张                    │
│  选中后展开完整机制卡          │
├─────────────────────────────┤
│  三、难度                    │
│  借住 / 常客 / 归古堡所有      │
│              [ 进入古堡 ]     │
└─────────────────────────────┘
```

- 不再有 8 名预设角色、职业分配、空缺、同住。
- 外观只影响头像，不影响数值。
- 四维总和必须为 24 才能进入；职业不参与校验。
- 「进入古堡」写入初始状态并切到白天；职业专属道具直接进背包。

### 3.2 白天主视图

默认停在「地图」页签。

**地图页**

```
┌─────────────────────────────┐
│ 公共层        玩家房间       │  两个页签
├─────────────────────────────┤
│  ┌────────┐ ┌────────┐      │
│  │长餐桌厅 │ │ 画廊   │      │  12 个房间卡
│  │●●○ 中  │ │●●● 高  │      │  风险点 / 危险度
│  │锈蜡     │ │蜡瞳     │      │  品阶倾向色条
│  └────────┘ └────────┘      │
│  ┌────────┐ ┌────────┐      │
│  │ 书房   │ │ 第九间  │      │
│  └────────┘ └────────┘      │
├─────────────────────────────┤
│ 当前：走廊 · 剩余 6 小时      │
└─────────────────────────────┘
```

- 房间卡：房间名、风险点（1–3 个实心点）、品阶倾向（两枚色块）、探索状态（已搜/未搜/有异变）。
- 大厅固定显示在网格入口，标记为「大厅」，不参与刷新，样式与普通房间区分。
- 「玩家房间」页签显示自己的房间与四项设施；单人局不再有住处列表。
- 点击房间 → 房间视图（同一区域替换，不新开页）。

**房间视图**

```
┌─────────────────────────────┐
│ ← 返回       画廊    ●●● 高   │
│ 陈设描述（两行，随房间变化）    │
├─────────────────────────────┤
│ 可搜索点                     │
│  ┌──────┐ ┌──────┐ ┌──────┐ │
│  │肖像  │ │抽屉  │ │地毯下 │ │  剪影/已搜状态
│  │ ?    │ │ ?    │ │ 空    │ │
│  └──────┘ └──────┘ └──────┘ │
├─────────────────────────────┤
│ 自带放置道具：蜡像替身（骨）    │
│ [ 搬走 1h ]                  │
├─────────────────────────────┤
│ 危险提示：此房间有东西在看你    │
│ [ 搜索 1h ]  [ 返回 1h ]      │
└─────────────────────────────┘
```

- 搜索点用物件名 + 剪影，不提前暴露品阶（嗅探者职业的被动除外）。
- 搜索后弹出道具卡（品阶色、效果、占格），并写入日志。
- 危险触发时用红色边框与一次抖动，不弹窗打断。

**设施页**

- 部件条分四段，每段左上角标等级；耐久低于 30% 时条变红并轻微脉动。
- 升级按钮显示完整成本，不满足条件时灰显并在下方给单行原因（铜扣不足 / 材料不足 / 智识不足 / 时间不足）。
- 炉压用仪表条，占用接近上限时变橙色并提示「超载将停摆」。

```
├─────────────────────────────┤
│ ┌─────────────────────────┐ │
│ │      门（剖面）          │ │
│ │  门板 ███████░░░        │ │
│ │  门轴 ███░░░░░░░        │ │
│ │  门闩 ██████░░░░        │ │
│ │  门框 ████████░░        │ │
│ │   裂纹随耐久出现          │ │

```

- 门剖面是夜晚的主视觉：四段门板、门轴、门闩、门框，裂纹 SVG 随耐久下降逐条出现。
- 怪物列表显示「种类 + 类型（破门 / 击杀 / 精神 / 盗窃 / 封锁）+ 本更意图」，不显示精确伤害。
- 逼近度用 6 个点表示本夜剩余更数。
- 每更结算后，门条与怪物意图更新，并生成一条日志。

**外出子视图**

```
┌─────────────────────────────┐
│ 外出 · 携带品阶：蜡          │
│ 仇恨 +1（蜡阶携带者）         │
├─────────────────────────────┤
│ 可去：长餐桌厅 · 洗衣房       │
│ ┌────────┐ ┌────────┐       │
│ │长餐桌厅 │ │洗衣房  │       │
│ │异变 ●●│ │无异变  │       │
│ └────────┘ └────────┘       │
├─────────────────────────────┤
│ 房间无人看守，门伤害 +30%     │
│ 遭遇概率 28% · 逃脱消耗 4 体力 │
│ [ 确认外出 ]  [ 留下 ]        │
└─────────────────────────────┘
```

- 夜间地图只显示相邻房间；已异变的房间有标记，吸引玩家冒险。
- 携带最高品阶与仇恨加成必须显式展示，让玩家自己算账。
- 遭遇概率 = 25% + 最高品阶仇恨 × 3%，在确认前直接列出。

**入室阶段**

```
┌─────────────────────────────┐
│ 门破了 · 第5夜 第4更          │
│ HP ██████░░ 6/10             │
├─────────────────────────────┤
│ 入室怪物：                    │
│ 裂口者（击杀型）本更将撕咬你   │
│ 叩门者（破门型）正在砸设施     │
├─────────────────────────────┤
│ [用药] [封门] [逃跑] [硬撑]    │
└─────────────────────────────┘
```

- 击杀型每更扣血，破门型只破坏设施；没有击杀型在场时不会持续掉血。
- 封门：木料 ×2，体魄判定 8，成功赶出怪物并获得 30% 总耐久临时护盾（天亮清零）；失败受伤 2；每夜 1 次。
- 逃跑：体力 -2，体魄判定 8；破窗锤/绳索 +2，烟幕弹必成；钉墙者在场时难度 +2，且破窗锤/绳索失效。
- HP ≤ 3 时整屏加红色边缘与心跳动效。阈值统一由 `HP_LOW = 3` 常量提供，01/02 不各写一份。
- 天亮后回到白天；被打爆的部件保持 0 耐久，其余部件保持破门时数值，需要修理。

### 3.4 天亮日报

```
┌─────────────────────────────┐
│ 第 3 天 · 天亮了              │
├─────────────────────────────┤
│ 厨娘今天没出现在长餐桌厅       │
│ 当铺老板被夜里的动静吓跑了     │
├─────────────────────────────┤
│ 获得：铜扣 +6  夜露 +1        │
│ 损失：门轴 -40                │
│ 注视：12 → 明日怪物增强        │
├─────────────────────────────┤
│ [ 开始第 3 天 ]               │
└─────────────────────────────┘
```

- 日报是唯一允许整屏停下的界面，给玩家喘息与规划。
- 日报必须列出：HP / 体力 / 恐惧的天亮回复、被打爆的门部件与修理材料、获得的夜露与注视变化。
- NPC 离开、玩家死亡用文字直述，不做煽情演出，留给聊天楼层。

### 3.5 死亡结算

- 显示存活天数、死因（HP 归零 / 门轴断裂 / 恐惧失控 / 夜间外出失踪）。
- 列出本局收集到的最高品阶道具与见过的房间数量。
- 一个「重新进入古堡」按钮，回到开局页。

### 3.6 胜利结算

- 撑过第 9 夜或集齐 3 件无名后触发。
- 显示存活人数、离开古堡的名单、本局最高品阶、收集到的无名道具。
- 一个「重新进入古堡」按钮，回到开局页。

## 4. 视觉规范

### 4.1 色板

| 变量 | 值 | 用途 |
|---|---|---|
| `--ink-900` | `#0d0b0a` | 页面底色 |
| `--ink-800` | `#14110f` | 面板底色 |
| `--ink-700` | `#1c1815` | 卡片、输入区 |
| `--line` | `#3a322a` | 分隔线、边框 |
| `--paper` | `#e8e2d0` | 主文字 |
| `--paper-dim` | `#9a9285` | 次要文字 |
| `--wax` | `#d9c07a` | 强调、可交互 |
| `--candle` | `#f0c070` | 烛光高亮 |
| `--rust` | `#a5714a` | 锈阶、警告 |
| `--blood` | `#7d2b2b` | 危险、低耐久 |
| `--eye` | `#7a5aa0` | 瞳阶、异常 |

### 4.2 品阶色

| 品阶 | 色值 | 视觉处理 |
|---|---|---|
| 尘 | `#8a8578` | 灰褐文字 |
| 锈 | `#a5714a` | 锈红文字 |
| 蜡 | `#d9c07a` | 蜡黄文字 + 1px 内发光 |
| 骨 | `#ddd6c2` | 骨白文字 |
| 瞳 | `#7a5aa0` | 紫文字 + 微脉动 |
| 无名 | 渐变 `#b8a0d8 → #8fc0b0 → #d8b0a0` | 名称用背景裁切渐变文字 |

### 4.3 排版与形状

- 标题：`Noto Serif SC`, `Source Han Serif SC`, 宋体，字重 600。
- 正文：系统无衬线（`-apple-system`, `PingFang SC`, `Noto Sans SC`）。
- 数字（资源、耐久）：等宽（`tabular-nums`），避免跳动。
- 圆角 2–4px，边框 1px `--line`，阴影只用内阴影与极淡外阴影。
- 纹理：一层 CSS 噪点（`radial-gradient` 叠加，opacity 0.03），不使用图片资源。
- 所有图标为内联 SVG 线性图标，不用 emoji。

### 4.4 动效

| 场景 | 效果 | 时长 |
|---|---|---|
| 烛火 / 灯 | `opacity` 与 `filter: brightness` 呼吸 | 3s 循环 |
| 门被撞击 | `translateX` 抖动 ±2px | 120ms |
| 门耐久跌破 30% | 红色内阴影脉动 | 2s 循环 |
| 怪物逼近 | 暗角阴影从边缘推入 | 600ms |
| 搜索揭示 | 卡片从 `opacity 0 / translateY 4px` 淡入 | 220ms |
| 天亮点亮 | 整体色温从冷转暖 | 800ms |

- 尊重 `prefers-reduced-motion`，全部动效可关闭。

## 5. 交互规则

- 所有数值操作必须来自点击，聊天文本不产生数值变化。
- 一次点击 = 一个动作，动作立即结算并写入状态，**不排队、不撤销**。
- 动作消耗时间后，顶栏时间与体力即时更新；时间耗尽自动切黑夜。
- 面板滚动位置在视图切换时保留（地图 → 房间 → 返回）。
- 手机端最小点击热区 44×44px；房间卡与搜索点整块可点。
- 危险与失败不弹模态框，用边框、抖动、日志行表达，避免打断对话。
- 冷却与条件不满足的按钮保留可见但灰显，附一行原因，不用 tooltip（手机无悬停）。
- 职业主动技能入口固定在设施页顶部，显示名称、剩余次数、冷却；没有次数时灰显。
- 体力 ≤3 时，搜索与外出按钮附「体力不足，成功率下降」提示；体力 = 0 时禁止外出。

## 6. 数据流

```
┌────────────┐   点击     ┌──────────────┐
│ Vue 组件    │ ────────→ │ game/actions │
└────────────┘           └──────┬───────┘
                                │ 纯函数
                         ┌──────▼────────────┐
                         │ 新 stat_data.$game │
                         └──────┬────────────┘
                                │ Mvu.replaceMvuData
                         ┌──────▼────────────┐
                         │ 当前楼层 MVU 变量  │
                         └──────┬────────────┘
                                │ 事件 + 主动刷新
                         ┌──────▼────────────┐
                         │ projection.js      │
                         │ → stat_data._投影  │
                         └──────┬────────────┘
                                │ 宏注入
                         ┌──────▼────────────┐
                         │ LLM 叙事（只读）   │
                         └───────────────────┘
```

- 面板与 LLM 共享同一份 MVU 状态，但写入口唯一：`game/actions`。
- LLM 只读 `_投影` 的约 120 字摘要，不接触完整状态。
- 同层面板只在最新楼层可操作；历史楼层只读。
- 事件协议见玩法案第 10 节。

### 7.3 刷新算法（伪代码）

```js
function refreshPublicRooms(state) {
  const rng = mulberry32(hash(state.seed + state.day + 'rooms'))
  const pool = ROOMS.filter(r => r.id !== 'R24')
  const picked = weightedSample(pool, 11, rng, r => riskWeight(r, state.day))
  if (!picked.some(r => r.id === 'R23')) picked[10] = ROOMS.find(r => r.id === 'R23')
  return picked.map(room => ({
    ...room,
    points: Array.from({ length: room.points }, () => {
      const item = rollItem(rng, room.gradeBias, 'day')
      const danger = Math.max(
        room.danger + (item.grade >= 'wax' ? 1 : 0),
        item.grade >= 'bone' ? 2 : 0,
      )
      return { item, danger, searched: false }
    }),
    furnishing: null,
  }))
}

function nightMutation(state) {
  const rng = mulberry32(hash(state.seed + state.day + 'night'))
  for (const room of state.publicRooms) {
    if (rng() < 0.10 + state.day * 0.03) {
      room.furnishing = rollItem(rng, room.gradeBias, 'nightHigh')
    }
    // 未搜索点按夜间权重重新生成
    room.points.forEach(p => {
      if (!p.searched) p.item = rollItem(rng, room.gradeBias, 'night')
    })
  }
}
```

- 所有随机都带 seed，同一局同一天刷新结果可复现，便于调试与验证。
- 刷新只读数据表，不调用 LLM。

### 7.4 状态体积控制

- 房间与道具只存 id 与可变字段（数量、耐久），静态定义查表。
- 公共层 11 个刷新槽位 + 固定大厅 + 玩家房间；邻接表随槽位固定，约 12 项。
- 背包通常不超过 12 件；日志只保留最近 30 条。
- 单层 `stat_data` 目标 < 8 KB；配合 MVU 的变量自动清理控制旧楼层体积。
- 给 LLM 的只有 `_投影` 一段约 120 字的纯文本。

## 8. 实现顺序

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 | 数据表（房间/道具/怪物/职业/NPC/品阶）+ 纯逻辑 + node 校验脚本 | 刷新 100 次无重复、无越阶、seed 可复现 |
| P1 | 本地 Vue 原型：开局页、白天地图、房间、设施、夜晚、日报 | 一局完整跑通，无酒馆依赖 |
| P2 | 接入 MVU Zod 与楼层内渲染 | 刷新页面状态不丢、切楼层正常 |
| P3 | LLM 叙事层与事件协议 | 面板动作后楼层叙事与数值一致 |
| P4 | 视觉打磨、动效、移动端适配 | 手机竖屏可用，动效可关闭 |
| P5 | 平衡与真机验收 | 三档难度各跑一局，第 8 夜曲线合理 |

P0 与 P1 之间的边界最重要：**纯逻辑先跑通，再接 UI，再接酒馆，最后接 LLM**。任何一步都不能跳过。

## 9. 风险与待验证

| 风险 | 影响 | 应对 |
|---|---|---|
| MVU 写入与 LLM 更新块冲突 | 数值被覆盖 | `$` 前缀对 AI 不可见 + `VARIABLE_UPDATE_ENDED` 回滚 `$game` |
| MVU 版本差异（2025-11 后不再写聊天变量） | 宏读取不到状态 | 卡内锁定脚本版本，真机探针确认 `_投影` 宏 |
| MVU 变量自动清理 | 历史楼层面板读不到状态 | 历史楼层只读摘要，最新楼层才可操作 |
| 状态体积超出楼层预算 | 存档变慢 | 存 id 不存对象、日志 30 条、单层 < 8 KB |
| 后期怪物伤害曲线偏温和 | 终局压力不足 | 首版用 `10 + 夜数×4`，实机模拟后上调 |
| 消息楼层高度限制 | 面板被截断 | 面板自适应高度，必要时提供「展开」切到独立视口 |
| 状态体积膨胀 | 存档变慢、投影超预算 | 日志折叠、道具槽精简、投影摘要 |
| 手机端点击精度 | 误触 | 44px 热区、整卡可点、危险操作二次确认 |
| 夜间动画性能 | 掉帧 | 只用 transform/opacity，裂纹用静态 SVG 切换 |
| 房间刷新可被玩家记忆利用 | 失去新鲜感 | 每日排除昨日布局，第九间房随机 |
